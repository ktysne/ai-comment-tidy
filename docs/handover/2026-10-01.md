## 決定済みの判断

| 項目 | 決定 | 理由 |
|---|---|---|
| 検査の置き場所(2026-10-01、開発者) | ai-comment-tidy の `lint` コマンドにする | `check` の「コメントの行数」と同じ数え方を使え、字句解析を 1 か所で持てる |
| グローバルの CLAUDE.md の縮小(2026-10-01、開発者) | フックの導入と同時に行う | 規則の本文は毎セッション読み込まれる。機械で検査する部分を文章で繰り返す必要がなくなる |
| フックの入口 | `PostToolUse`(Edit、Write)と `PreToolUse`(`git commit`)の 2 つ | 実装の多くは Codex への委譲で、Claude Code の編集のフックを通らない。コミットはメインセッションが行うので、コミット前なら両方を拾える |
| 報告の範囲 | 比べる元(HEAD)に無かった違反だけ | 既存の違反を報告すると、変更と関係のない既存コメントを同じ差分で直させることになる |
| GitHub のリポジトリ(2026-10-02、開発者) | `ktysne/ai-comment-tidy` を非公開で作る | クロスレビューの記録を PR のコメントに残すには、リモートが要る |
| 実装するセッション(2026-10-02、開発者) | このフォルダーで新しいセッションを開いて行う | CodeGraph とクロスレビューの道具は、セッションの作業フォルダーのリポジトリに向く |
| `lint` の 3 点(2026-10-02、開発者) | 設計資料「開発者の判断が要る事項」の案のとおり。確定の違反はコミットを止める、英語だけのコメントは検査しない、Codex の実行者からの呼び出しはフックの運用を確かめてから足す | 開発者が推奨の内容で進めるよう指示した |

## 落とし穴

- `install-hooks` は、フックのコマンドに Node.js 実行ファイルの絶対パスを記録する。Node.js を入れ替えた後は登録し直す。
- フックはメインのチェックアウトのコードを実行する。そこで別のブランチへ切り替えると、すべてのセッションのフックがそのブランチのコードで動くので、メインのチェックアウトは main のまま使い、作業は worktree で行う。
- `D:\Desktop\Develop\コメント記述ルール.md` は、縮める前の CLAUDE.md の節の写しのままである。設計資料「この資料の範囲」がこの写しを参照している。
- グローバルの `~/.claude/settings.json` には、ほかのフックが既に登録されている。`install-hooks` は既存のフックを残し、変更があるときだけ `settings.json.bak-<日時>` の控えを作る。
- グローバルの CLAUDE.md は git で管理していない。縮める前に控えを作る。
- 検査の失敗で編集やコミットを止めない。止めると、フックごと外されて検査が働かなくなる。
- フックの入出力の形(標準入力の JSON の項目、終了コード 2 の扱い)は、Claude Code の版で変わりうる。登録後に動かないときは、まず公式の資料と照らす。
