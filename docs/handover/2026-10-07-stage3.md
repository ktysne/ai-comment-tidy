## 実装の条件

### run

対象の束、設定、細則、既存の状態と置き場を、書き込みの前にすべて確認する。
新規は基準コミットの detached HEAD で作業ツリーを作り、作業ツリーのバイト列で担当ファイルの写しと対象範囲全体のハッシュを保存する。
依頼文は `prompt` と同じ生成処理を使う。
状態の「用意済み」は、写し、ハッシュ、依頼文の保存後に書く。

通常の再開は基準の写しとハッシュを照合し、依頼文だけを更新する。
現在の対象範囲の基準ファイルのハッシュが全件揃っていることも確認し、対象範囲の拡大で欠けた場合は再開を拒否する。
用意済み、報告あり、検査済みの状態は保持する。
委譲中と取り込み済みは、`--fresh` を含めて拒否する。
準備途中で状態がない場合や写しが欠けた場合は、基準を取り直さず、確認して `--fresh` を使うよう案内する。
`--fresh` は指定した束の作業ツリーと生成物を作り直し、状態の補足も初期化する。
対象リポジトリに属し、基準コミットの detached HEAD である作業ツリーだけを削除する。

### delegate

`prepared` から `delegated` へ移し、実行 ID が返った後の同じ状態での追記を許す。
`--cancel` は `delegated` を `prepared` へ戻す。
実行者の起動や停止は行わない。
取消の前に実行者が止まっていることをメインセッションで確認する。

### report

`delegated` の束に報告を取り込み、`reported` へ移す。
本文の最後の JSON から三つの候補の配列を読み、状態の `report` に保存する。
JSON や監査行がなければ `notes` に記録する。
子プロセスやビルドの警告は、メインセッションが検査をやり直すための記録として残す。
候補の型、担当ファイルとの対応、基準の行番号の形を検証する。

### check

既存の `check --offline` と、束を取らない `--base` の呼び出しを保つ。
束を取る通常の検査は `reported` と `checked` に限る。
合格時だけ `checked` へ移し、不合格時は状態を保持して検査結果を記録する。
`--offline` は結果や状態を書かない。

### apply

検査の合格、main 以外の統合先、基準の祖先関係、統合先の担当ファイルが基準と同じであることを検証する。
担当ファイル以外へ書き込まない。
再検査の合格と取り込みの完了後に `applied` を記録する。
コミットはメインセッションが行う。

## 検証

実際の一時リポジトリと worktree で、CRLF の写し、担当外の変更検出、再開、保存失敗、取消、報告なし、検査不合格、統合先の衝突を確認する。
各コマンドが不正な状態や未知の版で書き込みを始めないことも確かめる。
段階 3 の最後は、状態の遷移を直列に通す結合テストを行う。
実際の AI への委譲は段階 4 の試行で行う。
