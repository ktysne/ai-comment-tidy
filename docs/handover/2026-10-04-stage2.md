| 項目 | 決定 | 理由 |
|---|---|---|
| `lint` の対象 | `scope.include` を見ず、`scope.exclude` と `languages` だけを使う | フックは設定の無いリポジトリにも当たる。`include` を求めると黙る |
| `languages` | キーは字句解析の `id` に限る。書けば拡張子の判定を置き換える | どの字句解析に渡すかが 1 通りに決まらないと、`stats` と `plan` の値が決まらない |
| `stats` と `check` の対象 | 順 1 で `scope` と `languages` に従わせる | `plan` の重みと `stats` の対象が食い違うと、束に入らないファイルが表に出る |
| 基準と重みの上限 | `plan.base`(既定 `origin/main`)と `plan.maxWeight`(既定 700)。`passes.<回>` には持たせない | 基準は `plan` の時点で SHA に解決して束の定義に書くので、回ごとに持つ必要が無い |
| 束の寄せ方 | 同じディレクトリの同じ語幹を 1 単位にし、パスの順に並べて上限の手前で区切る | `.h` と `.cpp` に加え、`.hpp` と `.inl` も同じ規則で寄る |
| 置き場と状態 | 段階 2 で `src/paths.js` と `src/state.js` を定め、遷移の表に無い遷移は 2 で止める | 段階 3 の全コマンドが依存する。後から形を変えると全部に波及する |
| 版 | 束の定義と状態のファイルに `schemaVersion` を持たせ、知らない版は 2 で止める | 道具の版が変わっても、古いファイルを誤って読まない |
| 束の名前と回 | 回の頭文字と連番(`V01`)。束を取るコマンドは `--pass` で回を受け、省けば唯一の回を使う | 束の名前は回の中でだけ一意である |
| `prompt` の位置 | 作業ツリーが無くても新規として出せる | `run` の前に依頼文を確かめられる |
| 禁止の語の検査 | 細則から埋め込んだ文にだけ当てる。定型文はテストで守る | 全文に当てると、作業ディレクトリのパスのような定型文で止まる |
| 判定基準の雛形 | `templates/criteria.md` に置き、本文はメインセッションが書く。3 つの見出しを必須にする | 移行元の汎用部分を組み直す判断は依頼文に書き切れない |

## 順 1 の設計

- 設定の読み込みと検証を `src/config.js` に置き、`loadLintConfig` はその上の薄い包みとして残す。`--repo` と `--config <絶対パス>` の受け方は `check` の形に全コマンドでそろえる。
- glob の照合は `src/lint/run.js` から `src/glob.js` へ移す。最初に、`{h,hpp}` の候補と、`**/*.h` がルートの `a.h` に当たることをテストで確かめる。
- 言語の判定は `languageFor(path, config)` の 1 か所にし、設定が無ければ `languageOf` に落とす。
- 既存の `scope.exclude` のフォルダー名の書き方(`third_party`)は、`/` を含まないパターンとして今までどおり当たる。

## 順 2 から 5 の設計

- 順 2: `init` の言語の推定は作業ツリーの読み取り口の一覧から取る。ルートの `CMakeLists.txt` と配下のソースを持つ構成をテストに含める。雛形のテストは、3 つの見出しの解析を通ることと、禁止の語を含まないことを確かめる。
- 順 3: 重みは基準コミットの読み取り口から `fileStats` と `commentBlocks` を直接呼んで求める(`stats` の JSON を経由しない)。同じ基準と設定から同じ束の定義になることをテストにする。
- 順 4: 依頼文の見出しと埋め込みは設計資料「依頼文」に従う。状態の遷移の表は、`delegate` の 2 回の呼び出し(実行 ID の後からの記録)を含めてテストにする。依頼文に書くパスの形は 1 つの関数で決める。
- 順 5: 進み具合の基準側の値は、基準コミットの読み取り口から `readMany` で取る。束の定義の形は変えない。
